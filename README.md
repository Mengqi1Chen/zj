## 快速启动

Python 3.10 或更新版本，无需安装第三方依赖。本地可以不配置 API Key 启动，用于验证安全规则、精确检索和关键词降级；这种模式不会调用 OpenAI，不能作为最终线上 Agent 验收。在本目录运行：

```powershell
python -m apx240 --serve
```

打开 http://127.0.0.1:8765。也可双击 `start.cmd`。服务仅绑定本机地址；按 Ctrl+C 停止。

命令行和自测：

```powershell
python -m apx240 "A203，设定165°C，实际128°C，加热电流0A，没有烟雾和焦味。"
python -m unittest discover -s tests -v
```

接口：`POST /api/diagnose`，请求 `{"description":"A310，气压低"}`，响应为 FaultReport JSON。GET /health 为存活检查。页面可下载诊断报告和工单 JSON；服务不保存故障描述。

## 架构与目录

```text
web/index.html                         结构化现场输入、报告、原文证据卡片、工单与复核
apx240/server.py                       本地 HTTP / JSON API
apx240/engine.py                       Safety Precheck 与诊断状态流
apx240/observations.py                 现场读数、单位换算、否定与冲突
apx240/retrieval.py                    精确报警码 / 17 个语义文档块 / 关键词降级
apx240/providers.py                    OpenAI 兼容接口、超时与响应约束
apx240/model_review.py                 模型结构化输出、引用验证与候选排序
apx240/validation.py                   最终报告与工单一致性校验
apx240/knowledge.py                    只读加载、哈希与引用原文校验
apx240/models.py                       FaultReport / Evidence 数据结构
knowledge_mounts/apx240-v1/            PDF、逐页文本、结构化索引及 manifest
reference_library/                    12 条未核验外部模板（隔离，不参与诊断）
apx240/sessions.py                    持久会话、版本、读数更正及安全锁定
skills/apx240-fault-diagnosis/SKILL.md  领域行为协议
tests/                                回归、模型适配、检索与 36 条标注样例
examples/                             三组输入与真实生成的报告
docs/IMPLEMENTATION_PLAN.md            分阶段实现与验收计划
```

状态流：输入校验 → Safety Precheck → 精确/候选检索 → 手册与历史证据 → 原因证据分层与下一问选择 → 引用校验 → SAFE_BLOCKED / INFO_REQUIRED / EXPERT_REQUIRED / REPORT_READY → 工单草稿。多轮补充后对比上一版报告，生成诊断变化说明。

安全阻断覆盖普通排查步骤。`status` 表示当前流程位置，`expert_required` 独立表示是否需要专家，因此可以同时“信息不足”和“需要电气专家”。高风险仍可显示手册可能原因，但只保留停机及隔离前置步骤。

## 知识与 codewiki 的结合

- 原文未声明发行版本，使用源 PDF SHA-256 前缀作为快照版本，完整哈希保存在 manifest。
- 程序只读知识目录，每次请求验证受管理文件哈希；没有上传、修改或学习回写接口。
- 原始 PDF、逐页文本与派生 JSON 一同保存。结构化报警、历史、维修和安全规则均来自原文，检索关键词和追问清单属于应用规则。
- 证据记录文件名、PDF 物理页码、章节、来源编号、chunk_id、版本、片段以及 historical_only；引用片段必须出现在对应原文页。
- 这是借鉴 codewiki 的知识治理设计，未连接用户的 codewiki 客户端或远程知识服务。
- 只读由应用访问路径约束，哈希可检测文件意外变更；并非操作系统只读挂载或防恶意篡改签名。可写 manifest 的人可以更新快照；生产版需只读卷和受信任发布签名。

## 三个稳定验收样例

| 输入 | 预期行为 |
|---|---|
| A203，设定165°C，实际128°C，加热电流0A，没有烟雾和焦味。 | INFO_REQUIRED；追问预热及剩余安全信息；电气专家=true；引用 A203/H02/WO-240-042；不认定 H1 已损坏 |
| A520，输送段有金属摩擦声，机器剧烈振动。 | SAFE_BLOCKED；立即停机升级；普通排查被阻断 |
| A310，气压低，设备动作变慢。 | INFO_REQUIRED；追问上游/设备端气压及漏气声；不把历史滤芯堵塞当作当前根因 |

测试另覆盖无报警码、未知码、禁止操作、混合报警、全角输入、否定句、全部报警、快照变更、伪造引用和空输入。

## 当前边界与下一步

本版已具备**规则约束下的 OpenAI 模型审阅链路**。模型能对现有候选排序、提取可校验的现场片段并提出风险升级；不能生成或修改维修动作，不能覆盖停机决定。本机真实模型与 Embedding 联调已经通过；公网部署仍必须在 Render 中配置模型名和密钥，并在最终网址重新验证。

已完成：7 个报警码、5 条安全规则、5 个案例、5 条维修记录、证据校验、工单草稿、网页/API/CLI、自测。现场解析支持温度、电流、上下游气压及 MPa/kPa/bar 换算；H02/H03 逐项比较相同、不同和未知，只有已提取条件全部相同时提高对应候选优先级，不确认根因。多个不一致读数、历史与现场混杂、型号不符、风险不确定或实际温度超过手册稳定上界时，执行 SAFE-05 转专家。超过稳定范围被视为需核对的风险，不等同于手册定义了损坏阈值。

语义双通道已实现：精确码仍是主证据，另按模块召回报警、历史案例和维修文档；无报警码时返回候选，要求用户确认。向量采用余弦相似度、可配阈值、版本与模型隔离的内存文档缓存：

```text
APX_EMBEDDING_URL=<完整 HTTPS embeddings 接口地址>
APX_EMBEDDING_MODEL=<部署的模型名>
APX_EMBEDDING_KEY=<密钥，仅通过环境变量提供>
```

启用后会向配置的服务发送现场描述和相关知识。本地未配置时使用明确标注的 `lexical_fallback`；公网服务拒绝在模型或向量接口未配置时启动。阈值默认 0.35 是初始参数，未经真实业务数据标定。危险/冲突/未知报警在远程调用前阻断。向量响应异常或服务失败时回退关键词，页面会显示本次实际使用的模型与检索状态。

模型接入变量、运行方式和验收方法见 [模型接入说明](docs/MODEL_SETUP.md)。本项目只使用 `APX_*` 配置，未使用其他工具的凭据。模型失败时不自动重试，不记录供应商错误原文或密钥。

限制：确定性解析仍有语言覆盖边界；不进行复杂时间线/测点推理，混合历史描述保守转专家；模型只能提交可通过规则校验的数值片段。历史比较不涵盖所有时间和部件条件。当前支持在同一会话补充信息或更正读数。当前只实现 OpenAI 兼容 Chat Completions 协议。未连接飞书或真实设备，尚未完成生产安全评审。

外部模板已隔离，不参与检索和诊断，见 [EXTERNAL_CASES.md](docs/EXTERNAL_CASES.md)。24 条旧标注存在问题，已标为不可验收草稿，见 [案例审计](docs/GOLDEN_CASES.md)。
